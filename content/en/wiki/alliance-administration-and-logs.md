# Alliance Administration, R4/R5 & Logs

> **Last verified:** 8 Aug 2026  
> **Confidence:** High for documented event permissions and current log structure; not a complete permission matrix.

Alliance ranks are not only social labels. R4 and R5 receive operational permissions in several event and administration systems.

## Confirmed R4/R5 event permissions

Current public sources document examples such as:

- **Armory Assault:** alliance leader or R4 can register the alliance;
- **Bio-Mutant:** R4+ can start/schedule Frankenstein;
- **Allied Power:** R4/R5 can refresh Alliance-type tasks;
- other alliance events may grant comparable initiation or registration permissions.

The exact permission set is feature-specific, so the Wiki does not assume that every R4 permission applies everywhere.

## Alliance Logs

Official patch notes show the log system being actively redesigned:

### December 2025

Alliance Log was split into **War** and **Members** tabs for readability.

### January 2026

A new **Events** tab was added to track alliance administrative actions such as event initiations, while the Wars tab was optimized to retain key battle records.

This means event scheduling and other administrative actions can leave an auditable in-game trail.

## Practical leadership use

A healthy R4/R5 operating model usually separates responsibilities such as:

- event registration and scheduling;
- member administration;
- battle monitoring;
- alliance tech focus;
- territory/structure coordination.

These are recommended operating categories, not hard-coded role names from the game.

## Server policy boundary

The game grants permissions. It does **not** define how Server 504 must distribute authority among alliances or council members. Those governance decisions remain in the Charter / Operational Codex.

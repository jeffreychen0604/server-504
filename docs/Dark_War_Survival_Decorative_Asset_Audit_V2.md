## 1. Purpose

This document replaces the earlier assumption that the website only needs more decorative graphics.

The core problem is not asset quantity. The core problem is that the current decorative system is insufficiently grounded in the actual visual language of **Dark War: Survival**.

The V2 direction is therefore:

> **Learn from the game's UI structure first, then from its mood art.**

The website should not imitate screenshots literally, but its decorative system should feel immediately familiar to players because it reuses the same kinds of visual cues:

- chunky game panels;
- physical event centerpieces;
- reward trays and chest language;
- alliance banners and rank plates;
- Sealed Island shrine / oni / lantern / miasma imagery;
- clear PvP opposition language;
- building / stronghold identity for occupation content.

This audit is the source-of-truth for **Asset Spec V2**, the generator prompt pack, and the next Home reintegration pass.

# 3. Executive Diagnosis

## 3.1 What is currently wrong

The current Home decorative layer is visually more complex than the original dashboard, but it still does not feel sufficiently native to Dark War: Survival.

Its main failure modes are:

1. **generic cyber-fantasy decoration**;
2. repeated abstract line art with weak gameplay meaning;
3. overly dark, uniform treatment applied to unrelated event types;
4. decorative assets used as large watermarks instead of functional UI motifs;
5. insufficient use of the game's chunky, physical, object-centered event language;
6. too much invented tactical geometry and too little recognizable Dark War vocabulary.

The result is a website that says "dark game dashboard" rather than "Dark War: Survival Server 504 portal".

## 3.2 What the game actually does

The real game is visually broader and more playful than the current website.

Dark War: Survival combines:

- chunky casual/mobile-game UI;
- warm, tangible panels and buttons;
- strongly differentiated event themes;
- Japanese-inspired Season 4 environments;
- colorful rewards and rarity language;
- bold PvP versus composition;
- detailed physical structures such as Armory buildings;
- fantasy/survival character art.

The website should preserve its darker public-portal presentation, but it must borrow this **visual grammar**, not merely darken everything.

# 4. Core Visual Grammar of Dark War: Survival

## 4.1 The game uses a two-layer identity

The strongest conclusion from the supplied references is that Dark War: Survival does **not** force every screen into one universal palette.

It has two layers:

### Layer A — Shared game UI language

Consistent characteristics:

- rounded / softly beveled panels;
- thick tabs and headers;
- chunky buttons;
- clear card / slot grouping;
- white or cream text with strong contrast;
- tactile chest, banner, token and building imagery;
- generous use of gradients and bloom;
- highly legible state changes.

### Layer B — Local event / season identity

Examples:

- Pet Supplies → warm orange supply station + pet + paw chests;
- Lucky Chest → brown/gold roulette wheel + reward nodes;
- Maple Isle Shrine → blue forest shrine + torii + lanterns;
- Seek Divine Treasures → Daruma centerpiece + warm shrine lighting;
- Yum Corner → Japanese shop / noren / lantern identity;
- Lan's Shadow Shop → purple character/shop identity;
- Summer Paradise → bright tropical yellow/turquoise/beach identity;
- Alliance Duel → blue vs red/pink competitive split;
- Armory Assault → battlefield + fortified stronghold.

### Website implication

The site shell can remain **Sealed Island**, but individual events should retain their own visual identities.

Do not recolor every event into the same cyan/crimson/black scheme.

# 5. Form Language

## 5.1 Shapes

The game's UI is primarily:

- rounded rectangles;
- thick tabs;
- beveled plates;
- chunky containers;
- large physical objects;
- simplified icon silhouettes.

It is **not primarily built from**:

- thin sci-fi circuit lines;
- occult rings;
- hard geometric HUD reticles;
- cyberpunk neon framing.

## 5.2 Borders

Borders are usually visible and structural rather than purely decorative.

They communicate:

- tab state;
- selected state;
- rarity;
- team side;
- reward tier;
- card grouping.

Website rule:

> Borders should explain grouping or status before they decorate.

## 5.3 Corners

The current website uses angular sci-fi corner ornaments repeatedly. The actual game more often uses:

- soft clipped corners;
- rounded cards;
- thick mobile-game plates;
- framed banners;
- subtle illustrated motifs embedded in panels.

Therefore the existing generic corner-frame family should be considered temporary.

# 7. Typography Audit

The game uses a bold, friendly, high-contrast display language.

Common characteristics:

- heavy rounded display headings;
- white / cream fills;
- dark outlines or shadows;
- gold/orange emphasis for rewards and event names;
- very strong numerical hierarchy.

The website should **not** attempt to copy the game font everywhere.

Recommended website translation:

- retain a clean web font for body/data;
- use heavier, more game-like display treatment for event names, section flags and season headers;
- make numerical states and ranks more prominent;
- avoid thin techno typography.

The desired effect is familiarity, not literal reproduction.

# 8. Event Design Grammar

## 8.1 Events are object-centered

The supplied event screens consistently use a dominant physical centerpiece.

Examples:

- Pet Supplies → supply cabinet + dog + chest shelf;
- Lucky Chest → roulette wheel;
- Divine Treasures → Daruma;
- Maple Isle Shrine → torii / shrine;
- Season Pass → treasure chest;
- Yum Corner → noren storefront;
- Shadow Shop → Lan character art;
- Armory Assault → Armory stronghold.

This is a major difference from the current website, where event cards are decorated with abstract line-art watermarks.

### V2 rule

> Every important event card should have one recognizable centerpiece motif, not a generic decorative watermark.

## 8.2 Centerpiece placement on web

Do not reproduce the full mobile event screen.

Instead generate or crop a **vignette**:

- 25–45% of card width;
- typically anchored right or bottom-right;
- textless;
- soft fade into card background;
- clear negative space for HTML copy;
- recognizable at thumbnail scale.

# 12. PvP / Alliance Duel / Saturday KE Grammar

## 12.1 Real in-game PvP composition

Alliance Duel uses a very clear competitive language:

- blue side versus red/pink side;
- alliance banners facing each other;
- large gold `VS` focal point;
- progress percentage;
- weekly points;
- MVP / phase hierarchy;
- opposing server identity;
- teleport call-to-action for Enemy Buster.

## 12.2 Current website failure

Saturday KE currently uses:

- generic warning triangles;
- thin cyber/tactical lines;
- abstract red panel decoration.

This reads like a sci-fi security dashboard rather than Dark War: Survival.

## 12.3 Correct V2 direction

Saturday KE should become a **cross-server matchup board**.

Use:

- blue 504-side zone;
- red opponent-side zone;
- compact banner holders;
- central `VS` or conflict seam;
- server-number chip;
- Total CP meter;
- opponent rows visually framed as matchups rather than generic table entries.

### Important

Do not fabricate alliance banner graphics when no banner reference exists for a specific alliance.

Use neutral banner plates with alliance tags in HTML unless official/in-game banner artwork is available.

# 14. Armory Grammar

The Armory Assault screen provides a strong visual identity.

Key elements:

- large fortified Armory building;
- battlefield smoke;
- assault phase countdown;
- military outpost context;
- rewards / occupation framing;
- building-focused identity.

## 14.1 Current website failure

Armory Registration currently relies on tiny generic hex icons and text-only slots.

This fails to communicate:

- Armory as a physical stronghold;
- registered state;
- open / contested state;
- battle / occupation personality.

## 14.2 V2 Armory state system

Create four visual states:

### Registered

- small stronghold/building marker;
- illuminated frame;
- alliance tag prominent.

### Open Contest

- stronger amber/red contest plate;
- crossed conflict marks or opposing chevrons;
- contenders shown as HTML text;
- clearly distinct from `Available`.

### Available

- brighter open-slot state;
- no implied owner.

### Pending / Unknown

- dormant/desaturated state.

For Server 504's current Armory 4, the state should visually communicate:

> **Open contest — DUD · CMRD · IDS · iDGF**

without implying ownership.

# 20. ImageGen Production Rules

Every generated UI asset must follow these requirements.

## 20.1 Mandatory

- textless;
- no game logo;
- no fake alliance names;
- no fake reward values;
- no random mascot characters;
- no unrelated crest;
- no poster composition unless explicitly requested;
- designed for crop / panel integration;
- clear negative space where required;
- no full-screen UI recreation.

## 20.2 Composition instruction

Generator prompts should specify the intended position.

Examples:

- `right-edge vignette for a landscape event card`;
- `transparent corner decoration`;
- `soft atmospheric strip, no central focal object`;
- `cropped stronghold object occupying the lower-right 35%`.

## 20.3 Style instruction

Use:

- polished mobile strategy/survival game illustration;
- chunky physical props;
- readable silhouettes;
- painterly 3D mobile-game finish;
- controlled bloom;
- tactile materials.

Avoid prompt language such as:

- cyberpunk HUD;
- futuristic hologram;
- occult sigil;
- sci-fi interface;
- ultra-thin tactical linework;

unless a specific reference supports it.

# 21. Website Integration Rules

## 21.1 Shell vs local identity

The Home shell remains Sealed Island.

Local event cards keep their event identity.

Example:

- Home background → blue-violet Sealed Island;
- Summer Paradise card → bright tropical;
- Pet Supplies → copper orange;
- Lucky Chest → warm brown/gold;
- KE → blue/red matchup.

## 21.2 Text remains HTML

All user-facing text must remain HTML/CSS for six-language support.

Generated images must not contain:

- event names;
- dates;
- server numbers;
- `LIVE NOW`;
- `BIG EVENT`;
- alliance tags;
- rewards.

## 21.3 Decorative art must not become data

Artwork must never imply:

- official ownership;
- official threat level;
- event rewards not present in data;
- hero availability;
- alliance ranking not reflected by current data.

# 23. Acceptance Criteria

The V2 decorative pass is accepted only if all of the following are true.

## Game familiarity

A Dark War: Survival player should recognize the visual logic even if all text is hidden.

## Event differentiation

Pet Supplies, Lucky Chest and Summer Paradise must be visually distinguishable at thumbnail scale.

## Sealed Island identity

The Home shell should feel Season 4 through shrine / torii / oni / blue-violet atmosphere — not through a generic crest.

## Warfare authenticity

Saturday KE should read as a **server-vs-server Alliance Duel / Enemy Buster condition**, not a generic security warning.

## Armory clarity

Registered, Open Contest, Available and Pending states must be visually distinct without relying only on color.

## Reduced decorative repetition

No single corner/divider motif should appear identically across every panel.

## Readability

Decoration must not obstruct text or tables.

## Localization

No generated asset may require baked-in English text.

## Performance

Use optimized WebP / SVG. Decorative imagery must not reintroduce the earlier Home-loading problem.

# 25. Final Art Direction Statement

The Server 504 website should not look like a generic dark fantasy dashboard decorated with Dark War imagery.

It should feel like:

> **a clean public operations portal built from the same visual vocabulary that Dark War: Survival players already understand.**

That means:

- game-like structural hierarchy;
- object-centered event identity;
- Sealed Island atmosphere at the shell level;
- localized event palettes;
- Alliance Duel language for KE;
- stronghold language for Armory;
- useful decoration rather than decorative noise.

**V2 principle:**  
`Game UI grammar first → semantic asset second → atmosphere third → extra decoration last.`
